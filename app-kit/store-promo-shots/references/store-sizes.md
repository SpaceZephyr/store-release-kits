# 各商店尺寸

渲染器里的 key 就是下表第一列，`sizes` 数组里写几个出几套。

## Apple App Store

| key | 像素 | 说明 |
| --- | --- | --- |
| `iphone-6.9` | 1290×2796 | 现行主力。只传这一套，其余 iPhone 尺寸苹果会自动适配 |
| `iphone-6.5` | 1242×2688 | 老机型单独要的时候用 |
| `iphone-5.5` | 1242×2208 | 还在支持很老的机型才需要 |
| `ipad-13` | 2064×2752 | iPad 应用必传 |
| `ipad-12.9` | 2048×2732 | 旧版 iPad 尺寸 |
| `mac` | 2880×1800 | Mac 应用 |

每个尺寸最多 10 张，至少 1 张。列表页只露前两张。

## 微信小程序

| key | 像素 | 说明 |
| --- | --- | --- |
| `wx-share` | 1080×864 | 5:4 分享卡，转发到聊天/朋友圈时显示 |
| `wx-poster` | 1080×1920 | 带小程序码的推广海报 |

小程序详情页的截图直接用手机原始截图，不需要加框加文案，
所以那部分不走这个 Skill，走 `wechat-miniprogram-store-kit`。

小程序码必须从微信后台导出，这里只在版面上留位置。

## Chrome Web Store

| key | 像素 | 说明 |
| --- | --- | --- |
| `chrome-shot` | 1280×800 | 商店截图，至少 1 张、建议 3–5 张 |
| `chrome-marquee` | 1400×560 | 首页推荐位大图，只有被编辑选中才会用到 |
| `chrome-tile` | 440×280 | 列表小图 |

1400×560 和 440×280 的构图逻辑完全不同：大的能放一句话加一个界面，
小的只够放图标和产品名。别把一张图拉伸两次。

## 网页 / 社交

| key | 像素 | 说明 |
| --- | --- | --- |
| `og` | 1200×630 | Open Graph，发到社交平台时的预览图 |
| `web-hero` | 1920×1080 | 落地页首屏 |

## 竖版和横版

竖版尺寸默认用手机框，横版默认用浏览器窗口框。
Chrome 扩展和网页应用本来就是桌面产品，横版里塞一只整手机会很怪。
单张要改，在 slide 上写 `"frame": "phone"` 或 `"browser"` 或 `"none"`。
